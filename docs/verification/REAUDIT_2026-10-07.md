# ExamSathi current release re-audit — 7 October 2026

Reviewed local commit `e46b360`, live Pages deployment, source integration paths and automated checks. This is the complete findings list from this pass, not a guarantee that no undiscovered defects remain. No application code was changed or deployed during this audit.

## Checks performed

- 15 regression tests passed; TypeScript check passed.
- ESLint: 0 errors, 118 warnings.
- 22 live page/asset requests returned HTTP 200. The Pages `/api/ai/generate` request returned HTTP 404.
- Live profile → Starred → Launch Practice Drill reproduced an empty-question failure.
- Live roadmap → answer challenge → switch to REET reproduced immediate disclosure of the new solution.
- English toggle on roadmap did not translate the displayed Hindi/Punjabi challenge.
- Dependency audit: 5 high development dependency findings, 3 moderate production dependency findings, zero critical. These are advisory findings, not demonstrated exploits.
- Reviewed storage, question lookup, attempt initialization, study library, coach, roadmap, SRS, document extraction, metadata and service worker code. Earlier document-upload and scoring checks are recorded in FIX_REPORT_2026-10-07.md; not all were repeated in this pass.

## Confirmed defects and implementation limitations

P1 = major user flow/trust issue; P2 = normal functional defect; P3 = polish or maintainability.

| ID | Priority | Finding and reproduction/evidence | Required correction |
|---|---|---|---|
| B01 | P1 | Saved-question drill fails. Live Profile → Starred → Launch Practice Drill shows “No questions match these filters”. Profile writes custom questions/config to `sessionStorage`; MockTestClient reads `studyStorage`. | Use the same account-scoped transport at both ends; test exact question IDs. |
| B02 | P1 | Generated-question favorites/bookmarks disappear from the displayed vault. `getQuestionsByIds` searches only ALL_QUESTIONS, while computed/flashcard/notes questions are generated outside that bank. IDs alone cannot reconstruct them. | Persist question snapshots and resolve static and generated records. |
| B03 | P2 | Saved review can fail when current filters have zero questions: saved attempt replacement happens inside `if (loadedQuestions.length > 0)`. | Load saved review before checking current-bank availability. |
| B04 | P2 | Topic configuration can be discarded by MockTestBottomSheet: stores config in sessionStorage, reader uses studyStorage; navigation always targets topic-all even when defaultTopicId differs. | Put topic and complete config into a consistent route/storage contract. |
| B05 | P2 | Roadmap flashcard queue always zero: `getSRSSummary([])` iterates an empty list. Live queue displays zero. | Pass actual card IDs and refresh after reviews. |
| B06 | P2 | Roadmap challenge answer leaks across exams. Answer one challenge, switch exam; the new solution is already visible. | Reset selected answer/solution on track change. |
| B07 | P2 | “Daily” roadmap challenge is fixed per track; no date-dependent selection. | Rotate reviewed questions or rename to sample challenge. |
| B08 | P2 | Roadmap advertises task +XP but checking completion only saves booleans; no XP award is performed. | Define whether XP is actually earned and implement idempotent awarding or remove reward labels. |
| B09 | P2 | Roadmap “60-Day Adaptive Study Schedule” has only 3–5 milestone days per track; other days reuse the nearest milestone. | Provide daily plans or consistently describe it as a milestone roadmap. |
| B10 | P1 | Full SSC mock claims exceed engine behavior: roadmap promises 100 questions/60 minutes, but timer uses 54 seconds per available question, minimum 5 minutes; no 60-minute exam-specific duration is consumed. | Distinguish practice sets from full exam simulations and apply configured exam timing. |
| B11 | P2 | Library timer decrements one per interval callback; throttled/sleeping tabs drift from elapsed time. | Track deadline/elapsed wall time. |
| B12 | P2 | Library focus session is lost on reload/navigation; remaining time/running state are React state only. | Persist and recover session with pause/finish rules. |
| B13 | P2 | Library hours rounded to one decimal after each session; repeated 25-minute sessions accumulate rounding error. | Store integer elapsed seconds and round only for display. |
| B14 | P2 | Coach completion message is unreachable: final cycle sets breathCount=5 and breathStep=idle; completion requires breathStep != idle. | Use a separate completed state. |
| B15 | P2 | Coach nested timeouts have no unmount cancellation or stop control. | Track/cancel scheduled callbacks on stop/unmount. |
| B16 | P2 | Global language choice is ignored by profile, roadmap and coach; they do not read language state. English toggle leaves roadmap Hindi/Punjabi text unchanged. | Apply reviewed locale strings throughout the interface. |
| B17 | P2 | Page language is always `<html lang="hi">` regardless of EN/Punjabi selection. | Update document language and identify mixed-language sections. |
| B18 | P2 | Roadmap task-completion icon buttons have no accessible names or pressed state (confirmed in live AX tree). Coach accordions also lack expanded state. | Add accessible labels and state relationships. |
| B19 | P1 | Outdated capability claims remain: WhatsApp share text advertises predicted merit ranks; roadmap describes state rank maximization; profile promotes 20-year papers although provenance is under review. | Remove unsupported rank/archive claims everywhere, including metadata and share text. |
| B20 | P2 | Local recall saved notes are labeled “AI Generated Revision Note” / “AI Drill” irrespective of actual generation source. | Persist source/verification status and show accurate provenance. |
| B21 | P2 | Save All to Vault appends the same note IDs every click, producing duplicate records/React keys. | Deduplicate by stable question/note ID. |
| B22 | P2 | Study streak is displayed but no daily activity increment/reset logic is present; values originate from defaults, registration or demo profiles. | Compute streak from persisted dated study activity and label demo values. |
| B23 | P2 | Offline fallback depends on assets that are cached only when fetched normally. Install precaches HTML but not the offline route's JS/CSS dependencies; cold offline fallback is not assured. | Precache a self-contained fallback and its dependencies; test offline from a clean install. |
| B24 | P3 | Sitemap omits /syllabus/ and most generated lesson routes; it remains manually maintained. | Generate sitemap from supported routes/content. |
| B25 | P3 | Robots exclusions use root /admin and /api paths while deployed paths use /examsathi/admin and /examsathi/api. | Align robots paths with deployment base path; robots is not an access control. |

## Recommended order

1. Fix B01–B04 and add browser-level revision/retake integration checks.
2. Remove misleading provenance/rank/full-exam claims, then complete verified exam patterns.
3. Fix roadmap queue/state/rewards, language/accessibility, library and coach timers.
4. Deploy authenticated AI backend and complete email/OAuth configuration; test real services.
5. Expand verified syllabus/questions/resources, then cloud sync/admin publishing.
6. Resolve dependency findings, offline behavior and sitemap; finish device/accessibility checks.
